**生命周期阶段**：阶段 1 - 技术选型与论证  
**编写时间**：2026-10-10  
**状态**：APPROVED  

---

## 1. 业务诉求

在 Flutter (Dart) 展现层与 Rust 底层计算引擎之间，需要高效、安全、跨平台的通信机制：
- 无外部端口占用风险（防范防火墙拦截与本地端口冲突）；
- 跨平台兼容性良好（Linux, Windows, macOS, Android, iOS）；
- 统一的契约数据封装（请求/响应统一信封结构）。

---

## 2. 备选方案对比

| 评估维度 (权重) | 方案 A: C-FFI + JSON Envelope 信封契约 | 方案 B: 本地 HTTP REST / WebSocket 守护端口 | 方案 C: gRPC / Protocol Buffers |
|---|---|---|---|
| **网络隔离与端口安全 (30%)** | **100分**：纯进程内直接内存调用，零网络端口绑定，绝无端口冲突与防火墙拦截 | 40分：需绑定 localhost 端口，存在端口被占用、防火墙警告风险 | 50分：同样需要本地 TCP 通信管道 |
| **跨平台支持度 (30%)** | **98分**：Dart `dart:ffi` 原生支持所有桌面与移动 OS，无额外依赖 | 75分：移动端沙盒对本地 socket 有严格权限限制 | 70分：移动端 Protobuf 依赖包体积增大 |
| **性能与调用延迟 (20%)** | **95分**：微秒级（<0.1ms）调用开销，数据直接在内存序列化传递 | 60分：经过操作系统 TCP 栈回环，延迟约 1~5ms | 80分：二进制编解码快，但仍走网络栈 |
| **契约可读与调试性 (20%)** | **90分**：JSON Envelope 直观透明，契约文件易于 Mock 与静态校验 | 92分：REST/Swagger 工具健全 | 75分：二进制不可读，依赖特定调试工具 |
| **综合加权得分** | **96.4 分 (推荐)** | 62.9 分 | 69.0 分 |

---

## 3. 最终选型决定

**选定方案 A：C-FFI + 结构化 JSON Envelope 契约通信**
- Dart 端通过 FFI 绑定 Rust 导出的 C ABI 函数：`ai_reader_invoke(cmd_ptr, payload_ptr) -> resp_ptr`；
- 所有请求与响应遵循统一信封格式：`{ code, message, data, metrics }`；
- 生产环境直通原生库，测试环境可通过 Mock 契约处理器透明隔离。
