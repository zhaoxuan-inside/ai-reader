## 1. 背景与业务诉求

AI Reader 是一款定位于专业深度阅读与知识伴读的跨平台应用，要求：
1. **多端一致的像素级排版**：支持 Editorial 优雅衬线排版、严格 1.8em 黄金行高、上标锚点与边注折线指引，杜绝因操作系统渲染引擎差异造成的排版错位；
2. **极速高帧率交互**：正文长篇连续滚动、高亮下划线绘制、力导向概念图谱缩放拖拽均需保持 60fps+；
3. **全端自适应响应**：同一套代码库平滑支持桌面端（Linux/macOS/Windows）三栏专业工作台与移动端（Android/iOS）单栏触控沉浸交互。

## 2. 备选方案对比与评估

| 评估维度 (权重) | 方案 A: Flutter (Dart) (自绘引擎) | 方案 B: Electron + React/TS | 方案 C: 原生分别开发 (Swift+Kotlin+C++) |
|---|---|---|---|
| **跨平台一致性 (25%)** | **95分**：Impeller/Skia 统一自绘，全平台渲染完全一致 | 85分：Chromium 跨平台，但各端系统字体/滚动行为有细微差异 | 60分：不同端需重复开发，交互一致性维系成本极高 |
| **内存与启动性能 (25%)** | **90分**：AOT 编译为机器码，冷启动 < 400ms，常驻内存 ~60MB | 50分：Node+Chromium 进程开销，冷启动 > 1.2s，常驻内存 > 250MB | 98分：原生性能极致，但研发成本成倍增加 |
| **移动端原生能力 (20%)** | **95分**：天然兼顾 iOS/Android，触控手势、触感震动 (Haptics) 深度集成 | 40分：移动端需套壳 Capacitor/Cordova，流畅度较差 | 95分：完全原生，体验优秀 |
| **生态与图谱渲染 (15%)** | **88分**：丰富的绘图 Canvas、CustomPainter 与状态管理 (Provider/Riverpod) | 95分：Web 拥有成熟的 D3.js/ECharts 图表库 | 70分：原生图表库各端割裂 |
| **工程维护与团队契合 (15%)** | **92分**：单一 Dart 代码库，分层明确，易于开展契约与组件单测 | 85分：TS 生态成熟，但多端打包分发复杂度高 | 40分：需维护 3 套独立客户端工程 |
| **综合加权得分** | **92.3 分 (推荐)** | 71.5 分 | 71.8 分 |

## 3. 最终选型决定

**选定方案 A：Flutter 3.x (Dart)**
- **核心理由**：
  1. 统一的 Canvas 自绘保证了 5 大平台（Linux、Windows、macOS、Android、iOS）排版完全一致；
  2. 极佳的启动速度与低内存占用，适合长周期驻留后台的阅读应用；
  3. 强大的 CustomPainter 与手势系统，能够高保真实现边注连线、高亮选区与力导向关系网络。
