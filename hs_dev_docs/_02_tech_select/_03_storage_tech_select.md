## 1. 业务诉求与存储特征

AI Reader 采用**本地离线优先 (Local-First)** 架构，数据存储包含：
1. **书籍元数据与目录树**：文档标题、哈希校验、格式、页数、阅读位置指针；
2. **三级结构化节点与词频拓扑**：章节表、句子表、关键词表、共现关系网；
3. **高亮与边注交互数据**：选区锚点（Start/End offset, Page index）、颜色、批注内容；
4. **AI 会话与伴读模板历史**：多轮对话上下文、模板类型、Prompt 与响应历史。

## 2. 备选方案对比与评估

| 评估维度 (权重) | 方案 A: 嵌入式 SQLite 3 (WAL模式) | 方案 B: 纯 JSON / Flat 文件系统 | 方案 C: DuckDB 分析型数据库 |
|---|---|---|---|
| **ACID 与崩溃恢复 (30%)** | **98分**：工业级事务机制，WAL 预写日志保障断电零损坏 | 40分：易产生脏写、断电写截断导致文件损坏 | 90分：具备完整事务机制 |
| **关系查询与索引能力 (25%)** | **95分**：强大 B-Tree 索引，外键级联，支持复杂关键词连接查询 | 45分：需全量载入内存反序列化过滤，数据量大时卡顿 | 95分：OLAP 向量化查询极快 |
| **体积与资源消耗 (25%)** | **95分**：代码库嵌入极小 (<1MB)，单连接仅需几百 KB 内存 | 90分：几乎无额外体积 | 60分：二进制体积较大 (>30MB)，OLTP 点查开销偏重 |
| **生态成熟与跨端稳定性 (20%)** | **99分**：`rusqlite` 成熟可靠，全平台无缝兼容 | 90分：全平台通用 | 75分：移动端平台嵌入仍在演进中 |
| **综合加权得分** | **97.0 分 (推荐)** | 59.8 分 | 80.2 分 |

## 3. 最终选型决定

**选定方案 A：嵌入式 SQLite 3 (通过 `rusqlite` + WAL 模式)**
- 开启 `PRAGMA journal_mode = WAL;` 与 `PRAGMA synchronous = NORMAL;`；
- 遵循 `hs-dev-skill` DB 规范：强制自增 `id`, `created_at`, `updated_at`, `description`, `is_del`, `version` 审计字段；
- 所有结构化查询通过前向迁移与回滚脚本（V/U）原子版本管理。
