## 1. 背景与业务诉求

AI Reader 的核心计算与数据层包含如下核心挑战：
1. **多格式高保真解构**：需要高性能解析 PDF (含页面几何位置与文本提取)、EPUB (NCX/OPF XML 目录与 XHTML 内容)、Markdown (AST 块解析) 及纯文本；
2. **离线三级 NLP 与图谱计算**：在本地离线对 10 万字大篇幅书籍进行分词、TF-IDF/TextRank 关键词打分、共现矩阵与 PMI 权重计算，必须在 1.5 秒内完成，且不能引起 GC 停顿；
3. **跨端嵌入能力**：底层引擎需能够作为静态库或动态库直接嵌入桌面与移动端，零外部服务端依赖。

---

## 2. 备选方案对比与评估

| 评估维度 (权重) | 方案 A: Rust 嵌入式核心引擎 | 方案 B: Go 独立后台服务 | 方案 C: Python 守护进程 |
|---|---|---|---|
| **计算吞吐与无 GC 表现 (30%)** | **98分**：零成本抽象，SIMD加速，无 GC 停顿，10万字分析 < 1.0s | 82分：有 GC 开销，并发优秀，计算密集吞吐稍逊 | 55分：GIL 限制，大文本分词计算较慢，内存占用大 |
| **嵌入式与跨平台编译 (25%)** | **96分**：原生编译为 `.so`/`.dll`/`.dylib`/静态库，天然支持 FFI 嵌入 | 75分：CGO 跨平台交叉编译复杂，运行时体积大 (>30MB) | 40分：依赖 Python 运行时环境，移动端打包极其繁琐 |
| **内存安全性与鲁棒性 (25%)** | **98分**：所有权模型编译期保障线程安全与内存安全，零悬垂指针 | 90分：带 GC 内存安全，但并发下数据竞争需 runtime 规避 | 80分：动态类型，运行时易发生类型异常 |
| **生态成熟度 (PDF/NLP/SQLite) (20%)** | **90分**：`lopdf`, `epub`, `pulldown-cmark`, `jieba-rs`, `rusqlite` 生态成熟 | 88分：`pdfcpu`, `gse`, `go-sqlite3` 生态齐全 | 95分：Python 在 NLP 领域生态极度丰富，但嵌入代价高 |
| **综合加权得分** | **95.7 分 (推荐)** | 83.7 分 | 64.0 分 |

---

## 3. 最终选型决定

**选定方案 A：Rust 核心计算引擎 (Rust 2021 Edition)**
- **核心理由**：
  1. 极致计算性能与无 GC 停顿，确保 10 万字书籍的离线 NLP 计算与图谱构建毫秒级完成；
  2. 原生编译支持跨架构（x86_64, aarch64, armv7）打包为动态/静态链接库，完美支持全平台原生嵌入；
  3. 强类型系统与六元组契约天然契合，能够构建高度健壮可靠的领域层逻辑。
