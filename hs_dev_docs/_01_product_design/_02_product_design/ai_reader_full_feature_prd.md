## 1. 产品愿景与定位 (Vision & Value Proposition)

AI Reader 是一款定位于**深度认知伴读、多格式统一排版、知识图谱穿透与全端自适应响应**的现代智能阅读工作台。

面对学术论文、经典大部头著作、技术规范与长篇文档，传统阅读器仅能提供单向视觉呈现，缺乏与知识上下文的深度互动。AI Reader 致力于重构数字阅读体验：
- **全格式无感统一流**：无论 PDF、EPUB、Markdown 还是 TXT，统一解构为结构化 AST 语义流，并辅以 Editorial 极简优雅排版；
- **空间感知与原版溯源**：在流式排版的同时，保留 PDF 物理页坐标与 Bounding Box，实现一键穿梭溯源；
- **沉浸式伴读心智**：iA Writer 风格黄金行高与右侧 Marginalia 边注基线对齐，打破割裂的独立聊天窗模式；
- **深度认知脚手架**：预置 4 大认知伴读模板（通俗化、逻辑链、批判性、术语拆解），使复杂概念快速被消化；
- **概念拓扑穿透**：离线三级 NLP（全文/章节/句子）关键词抽取与共现网络，配合目录思维导图，助力读者迅速把握全书脉络与概念网络；
- **全端无缝体验**：桌面三栏专业工作台与移动单栏触控自适应无缝切换，数据本地离线持久化优先。

## 2. 目标用户画像与业务场景 (User Personas & Scenarios)

### 2.1 目标用户画像
1. **学术研究者 / 研究生（Persona A: Scholar）**：
   - 核心诉求：阅读动辄 30-80 页的双栏专业 PDF 论文，需要实时解析公式背景、专业术语，并精确对照原版图表与论述位置。
2. **知识工作者 / 深度阅读爱好者（Persona B: Thinker）**：
   - 核心诉求：阅读人文社科或经管类 EPUB/Mobi 电子书，要求排版极其纯净优雅（如 iA Writer）、注释随读随记并与原文段落并排锚定，便于导出至 Obsidian/Notion 等 PKM 工具。
3. **技术工程师 / 架构师（Persona C: Engineer）**：
   - 核心诉求：审阅复杂 Markdown/TXT 架构规范与 RFC，需要宏观把握全篇逻辑结构，通过思维导图和关键词拓扑网络快速反查关联设计。
4. **移动通勤读者（Persona D: Commuter）**：
   - 核心诉求：手机/平板单手交互，触摸长按段落触发平滑触感反馈与底部 AI 伴读抽屉卡片，回到桌面后进度与笔记自动一致。

### 2.2 核心业务场景与操作链路
- **场景 1（文档极速导入与本地书架）**：用户拖拽或通过系统文件选择器导入文件 -> 异步分块解构生成段落索引与元数据 -> 书架即时卡片呈现 -> 点击进入沉浸阅读。
- **场景 2（选区伴读与多轮追问）**：选中文本段落 -> 弹出极简操作胶囊 -> 点击“认知伴读-逻辑链剖析” -> 边注栏在对应段落右侧平滑展开伴读卡片，流式输出深入解读 -> 用户在卡片下方快捷追问并沉淀批注。
- **场景 3（全书概念穿透导航）**：点击侧边栏“概念图谱” -> 展示 PageRank 与 PMI 算出的高权重核心关键词共现图 -> 点击某核心概念节点（如“注意力机制”） -> 聚光灯聚焦，右侧列出所有关联段落与原文章节，点击直达。
- **场景 4（全篇结构思维导图）**：点击“思维导图” -> 目录树与章节主题词自动聚合为交互式思维导图 -> 支持折叠、展开、缩放与正文双向联动。

## 3. 功能矩阵规格说明 (Feature Matrix & Functional Specs)

| 模块编号 | 功能模块 | 核心能力描述 | 关键交互与性能指标 |
|---|---|---|---|
| **F-01** | **全格式统一解析引擎** | 统一支持 PDF、EPUB、Markdown、TXT 格式；解构为统一 Document AST，提取章节、段落、样式与嵌入媒体信息。 | 10 万字文档冷启动解构 < 1.5 秒；异步非阻塞 UI 线程。 |
| **F-02** | **双模阅读与 Editorial 渲染** | 1) 流式重排视图：严格遵循 1.8em 黄金行高、Typography 优雅衬线排版；<br>2) 原版画布视图：针对 PDF 呈现原始物理排版与空间锚点 [P.n ↗]。 | 60fps 平滑滚动；毫秒级模式无缝切换。 |
| **F-03** | **iA Writer 边注与高亮体系** | 桌面端右侧 280-320px 边注栏与正文段落基线对齐；支持 5 色高亮、下划线及文本锚点坐标持久化；支持导出 Markdown 格式笔记。 | 边注折线指引无遮挡；批注数据 100% 增量保存。 |
| **F-04** | **深度认知伴读与多轮对话** | 4 大认知伴读模板：<br>1) 通俗大白话解读；<br>2) 逻辑结构剖析；<br>3) 批判性辩驳与边界；<br>4) 核心术语卡拆解。<br>支持流式 Markdown 输出、代码高亮、公式渲染及多轮连续追问。 | 首字响应延迟 (TTFT) < 800ms；支持本地 Mock 降级与网络错误自动重试。 |
| **F-05** | **三级 NLP 概念图谱** | 本地离线全量计算：全文级 / 章节级 / 句子级关键词提取（TF-IDF + TextRank）；词间共现矩阵与 PMI 关联分析；交互式网络图谱可视化与原文章节反查。 | 纯本地离线计算，无需上传云端；支持 60fps 力导向拖拽与缩放。 |
| **F-06** | **结构化思维导图生成** | 深度结合文档目录 AST 与章节级核心词，自动提取全书知识树；支持全屏思维导图展开、分支收起、节点高亮及定位跳转。 | 节点秒级渲染，与正文阅读位置保持双向同步。 |
| **F-07** | **本地持久化书架与状态机** | 基于本地 SQLite 数据库；记录书籍元数据、封面、阅读进度百分比、批注列表、问答历史与用户首选项。 | 零网络依赖下完整功能可用；崩溃自恢复。 |
| **F-08** | **全端自适应响应布局** | 针对大屏（桌面端 macOS / Windows / Linux）采用“三栏工作台”（目录/图谱 - 正文 - 边注）；针对移动小屏（Android / iOS）自动自适应为“单栏极简 + 底部抽屉伴读卡片”。 | 屏幕尺寸无极拖动自适应断点平滑过渡。 |

## 4. 异常处理与系统边界 (Error Handling & Edge Cases)

1. **网络超时与 AI 接口不可用**：
   - 自动启用指数退避重试（最多 3 次）；
   - 超时后优雅切换为“离线降级提示”，保留用户输入草稿，支持一键“重试生成”；
   - 允许用户配置自定义 API Endpoint、API Key 及模型选型（如 OpenAI 协议、Gemini、本地 Ollama 等）。
2. **超大/损坏文档处理**：
   - 遇到损坏或密码保护的文档时，提供明确的前端友好弹窗提示；
   - 超过 50MB 的超大 PDF 执行渐进式按需加载（Page-on-demand），不一次性加载全量内存，避免 OOM。
3. **高并发并发写入与数据一致性**：
   - 本地 SQLite 启用 WAL (Write-Ahead Logging) 模式；
   - 批注、阅读历史采用原子写入事务，确保断电或强制终止应用零数据损坏。

## 5. 完成定义与验收准则 (Definition of Done - DoD)

1. **功能完备度**：全功能矩阵 F-01 至 F-08 全部实现，无任何空桩代码或假数据残留；
2. **跨端可用性**：Linux、Windows、macOS 桌面环境可正常构建并流畅运行，自适应交互在不同窗口分辨率下均符合排版规范；
3. **架构与工程规范**：严格遵循六元组标准化运行时设计规范（主方法、降级、补偿、度量、回调），测试分支覆盖率 ≥ 85%；
4. **质量门禁**：通过 `verify_consistency.py` 自动化三文件与索引门禁检查，通过 `dead_code_scanner.py` 死代码扫描。
